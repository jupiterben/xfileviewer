## install.bat 增加 HEVC（H.265）解码检测与引导

需求：Windows 安装程序检测 HEVC 扩展，缺少时引导用户安装微软官方 HEVC 视频扩展。

实现（改 `install.bat` + `README.md`，未引入新的 .ps1）：
- 判定顺序：① AppModel 包仓库里是否存在 `Microsoft.HEVCVideoExtension*`（HKCU 优先，再 HKLM）；② Media Foundation 里是否存在输入类型含 HEVC/H.265 子类型的解码变换。
- 关键事实：解码器把压缩格式放在 `InputTypes`、编码器放在 `OutputTypes`，所以只匹配 `InputTypes` 就能区分，避免把 NVIDIA / 微软的 HEVC 编码器误判成解码器。
- 子类型 GUID 十六进制串（FourCC 前 4 字节 + `00001000800000AA00389B71`）：HEVC = `48455643…`，H265 = `48323635…`，H264 = `48323634…`（用于阳性对照自测）。
- `reg query /f <hex> /d` 能匹配 REG_BINARY 的十六进制文本（子串匹配），这是纯批处理的检测基础。
- 商店产品 ID（已核实，容易记反）：`9N4WGH0Z6VHQ` = 来自设备制造商的 HEVC 视频扩展（免费，推荐）；`9NMZLZ57R3T7` = HEVC 视频扩展（付费 ~$0.99）。
- 交互：缺失时打印两条链接并询问是否打开商店；`XFILEVIEWER_NO_PAUSE=1` 只打印不询问；新增 `-SkipHEVC` / `--skip-hevc`。

踩坑：`if (...) else (...)` 复合块里的 `echo Skipped (-SkipHEVC).` 中的 `)` 会被 cmd 当成块结束符，报「此时不应有 .」——块内括号必须写成 `^( ... ^)`。另外 `set /p` 的提示串会吞掉行首空格，缩进不要用前导空格。

验证方式：脚本在 `:deps` 处截断生成临时骨架（去掉 npm/tauri/安装步骤），跑通 缺失/已检测(SkipHEVC)/阳性对照/答 Y/答 n/未知参数 六个用例；临时文件已删。

## libmpv 接管 Windows 视频解码（WebView 仅作回退）

需求：Windows 版内置 libmpv，由它直接解码并显示视频，前端继续负责控制条。解码库会随安装包分发，用户无需另装系统解码器。

实现：
- 前端把 `videoViewer` 拆成 `PlayerShell`（共享控制条/键盘/音量持久化） + `VideoBackend` 接口 + 两个具体后端（`nativeBackend` / `htmlBackend`）。
- `mountVideo` 同步构造 shell，异步 IIFE 决定后端；Windows + Tauri 走 native，失败或非 Windows 走 WebView。
- 平台门控：`isTauri()` 看 `window.__TAURI_INTERNALS__`（jsdom 里没有，老 UA 检查会误判 `(win32)`），`isWindows()` 收紧到 `/Windows NT/i`。两条都过才走 native，单边命中都退化到 WebView。
- 子窗口坐标必须给**物理像素**：HWND 是父 client 区的物理坐标。用 `getBoundingClientRect()` 取 CSS 像素再乘 `window.devicePixelRatio`，最后 `Math.max(1, …)` 兜底，否则高 DPI 下子窗口偏到屏幕左上角。
- mpv 实例管理：`native_video.rs` 从 `Mutex<Option<Player>>` 改成 `Mutex<HashMap<session, Player>>`，硬上限 `MAX_PLAYERS = 4`，超出按 `last_used` 淘汰最少使用；控制/状态命令都会刷新 `last_used`。`native_video_close` 现在找不到 session 时返回错误，便于上层识别"已被新会话替换"。
- mpv 自然尺寸 vs 显示尺寸：前端需要装窗口，所以从 `width`/`height`（解码后原始尺寸）取，不要 `dwidth`/`dheight`（会被容器拉伸）。
- 轮询：100 ms `setInterval` 读 `native_video_status`，`destroy()` 必清；测试用 `vi.useFakeTimers()` 验销毁后不再 invoke。

## 修复：native 视频播放时拖放文件失效

需求：视频用 libmpv 播放时，往窗口拖新文件无法打开。

根因（关键事实链）：
- wry 的拖放实现（webview2/drag_drop.rs）只在 **webview 创建那一刻** 用 `EnumChildWindows` 找到当时存在的子窗口（WebView2 的 HWND）并 `RegisterDragDrop`。
- mpv 的视频窗口（我们的 STATIC 宿主 + mpv 内部再建的渲染子窗口）是**后来**才创建的，没有注册 IDropTarget。
- OLE `DoDragDrop` 只查「光标下那个窗口」的 drop target，**不会向上走到 WebView2 兄弟窗口**（wry 之所以自己 EnumChildWindows 而不是只注册主窗口，就是因为这个）。
- mpv `--wid` 嵌入是非侵入式的：不子类化、不改宿主样式，它自己在 wid 窗口里建 `WS_CHILD` 渲染窗口并 `EnableWindow(self, 0)`；WS_DISABLED/WS_EX_TRANSPARENT 并不能让 OLE 命中测试跳过它。

实现（`video_drop.rs` 新模块 + native_video.rs 接线 + main.ts 监听）：
- `#[implement(IDropTarget)]`（windows crate 0.61；**implement 宏无条件可用，不是 feature**），CF_HDROP 从 `IDataObject::GetData` 取 `STGMEDIUM.u.hGlobal` 直接当 `HDROP` 用（无需 GlobalLock），`DragQueryFileW(0xFFFFFFFF)` 先取数量；Drop 后 `DragFinish` 释放。
- 宿主窗口 open 时立即注册；mpv 内部渲染子窗口异步出现，借 100ms status 轮询用 `EnumChildWindows` 找到后补注册（`Player` 持两个 `DropGuard`，析构时 `RevokeDragDrop` 在 DestroyWindow 之前）。
- 转发方式：`app.emit("video-file-drop", paths)` → main.ts `listen` 后走与 webview drop 相同的 `openPath(paths[0])`。

坑：
- windows-sys 0.61：`BOOL` 移到 `windows_sys::core`，`LPARAM` 留在 Foundation 且是裸 `isize` 别名（没有 `.0`）。
- windows crate 0.61 的 `#[implement]` 宏生成 `::windows_core::` 路径，**crate 必须直接依赖 windows-core** 才能解析（EB433）。
- 同一文件的两个 Edit 并行执行会互相覆盖（后者用旧快照写回），必须串行。

验证：cargo check/test（28 通过）、cargo build、tsc 全绿；本机 vitest 全 26 文件报 `Cannot read properties of undefined (reading 'config')`，与本次无关（node_modules 疑似 Linux 侧装的环境问题，pnpm shim 也损坏）。

## 用户案例：list_dir_files 报 267 (ERROR_DIRECTORY)

`[list_dir_files] [打开目录] Y:\NewG\douyin\济南最后的深情\2026：目录名称无效。 (os error 267)`

2. PowerShell `EnumerateFileSystemEntries` 73 项成功——Win32 层目录可读，问题在 app 内的 read_dir 调用栈。

## 修复视频原生解码器 ACL 拒绝问题（2026-09-05）
- 症状：播放视频时报 `native_video_open not allowed. Command not found`，回退 WebView 播放。
- 根因：Tauri 2 ACL —— 项目自定义权限 `allow-shell-commands`（permissions/shell.toml）白名单了 13 个命令，但视频管线的 9 个命令（native_video_open/layout/control/status/close、native_video_available、ffmpeg_available、hls_open、hls_close）从未加入白名单，invoke 被 ACL 拒绝；HLS tier-3 也因 ffmpeg_available 被静默拒绝而失效。
- 修复：新增 `src-tauri/permissions/native-video.toml`（identifier `allow-video-pipeline`，9 个命令），并在 `capabilities/default.json` 加入 `allow-video-pipeline`。cargo check 通过，gen/schemas/acl-manifests.json 已确认包含新权限。libmpv-2.dll（120MB）本就捆绑在 resources/mpv/，与 DLL 无关，警告信息中的 prepare:native 提示是误导。需重启 dev/重新打包生效。

## 视频上一个/下一个快捷键改为 ↑/↓ 箭头

`src/shell/sequenceKeys.ts`：视频分支从 PageUp/PageDown 改为 ArrowUp=-1（上一个）、ArrowDown=+1（下一个）。左右箭头仍归 seek（±5s，seek.ts 的 seekDeltaForKey），上下箭头在视频后端无占用，无冲突。控件条上（音量/进度条聚焦时）onControlKey 会 stopPropagation，滑块的上下键原生行为不受影响。同步更新 sequenceKeys.test.ts，vitest 4 通过 + tsc 无错。
