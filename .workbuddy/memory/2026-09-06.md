## 透明 overlay WebView：音量弹层浮上视频（续昨日的 bar 内弹层方案）

用户贴回「进阶做第二个透明 WebView2 子窗口叠在 mpv 上」的推荐，落地实现完成。

### 架构
- Rust `video_overlay.rs`（新）：`ensure/sync/teardown/capture_hwnd`。label=`video-overlay` 的透明子 webview（同一 SPA，`index.html`），`Window::add_child` 创建（tauri `unstable` feature，仅桌面）。
- **Z 序关键**：wry 子 webview 有自己的中间 HWND（类名 `WRY_WEBVIEW`）；`apply_bounds` 每次把 mpv 提到 HWND_TOP 后立即把 overlay 也提回 HWND_TOP（`SWP_NOMOVE|NOSIZE|NOACTIVATE`）。overlay HWND 在创建后按「GetWindowRect(mpv 宿主) 矩形匹配」枚举捕获，存入 `NativeVideo.overlay_hwnd`（usize，用 IsWindow 校验）。
- 实际依赖版本：tauri 2.11.5 / wry 0.55.1 / windows-sys 0.61.2（注意 CARGO_HOME 在 scoop persist，`~/.cargo` 是 stale 目录！）。dpi 类型在 tauri crate 根（`tauri::{Rect,Position,Size,Physical*}`），`PhysicalSize<u32>`/`PhysicalPosition<i32>`；HWND/LPARAM/RECT 均在 `Win32::Foundation`；windows-sys 0.61.2 无 `ClientToScreen`（用 mpv 宿主 GetWindowRect 做匹配基准绕开）。
- bounds 坐标系统一：前端 devicePixelRatio×CSS px = 物理像素，与 mpv SetWindowPos 一致；wry set_bounds 用 SWP_NOZORDER 不会乱序。
- 生命周期：open 时 ensure（幂等）+sync，layout 时 sync，close 时 teardown（否则透明层会吞图片/文档区域的输入）。
- capabilities：windows 加 `video-overlay`；权限 `core:webview:allow-set-webview-focus`（不是 allow-set-focus，版本里不存在）。

### 前端
- main.ts 按 `getCurrentWebview().label === "video-overlay"` 分支：overlay 走 `shell/videoOverlayPage.ts`，不 boot()（否则会偷 take_launch_path/双开 viewer）。
- playerShell：`popupMode inline|overlay`，native 打开成功后 videoViewer 调 `setPopupMode("overlay")`。hover/focusin → `ctx.onVolumePopup(true,{x,bottom,volume,muted})` → emit `video-overlay-cmd`；leave/focusout → 200ms 宽限 hide（`barHover||overlayHover` 任一存活则取消）。
- 事件协议：`video-overlay-cmd`(主→overlay)、`video-overlay-state`(音量变更广播)、`video-overlay-volume`(overlay 滑杆→主 shell setVolume)、`video-overlay-hover`(overlay 弹层 hover 保活)、`video-overlay-wheel`(滚轮翻页转发，video kind 用滚轮翻页)、`video-file-drop`(overlay 的 tauri onDragDropEvent → 主页 openPath)。
- 键盘无障碍：bar 内滑杆保持可聚焦（CSS opacity:0+pointer-events:none 而非 display:none），focusin 显示 overlay 弹层，方向键在主 webview 调音量、overlay 实时镜像。
- **Escape 竞态**：overlay 页里 main.ts 模块级 window keydown 会把 Esc 当「关闭窗口」——overlay 页用捕获阶段 (`addEventListener(..., true)`) + stopPropagation 拦截「弹层显示时 Esc 只关弹层」。
- 焦点：overlay 弹层关闭时 `getCurrentWebview().setFocus()` 还给主 webview（权限 core:webview:allow-set-webview-focus）。
- CSS：`html.overlay-mode` 背景透明 + 隐藏全部 app chrome；弹层 44×160，滑杆 20×136 垂直(writing-mode: vertical-lr; direction: rtl)，::after 8px 桥条保证跨 webview hover 连续。

## 真机反馈：视频画面不可见 → 透明探针调试

用户报告打开视频后「无法看到图像」，怀疑透明没生效。代码层排查结论：overlay 页样式/分支正确、wry 0.55.1 对子 webview 正确调 `ICoreWebView2Controller2::SetDefaultBackgroundColor(alpha=0)`（init_webview 内，不分 child/main）、子 webview 是普通 `WS_CHILD|WS_CLIPCHILDREN`（无 layered/NOREDIRECTIONBITMAP 扩展样式）。三个待区分假设：① overlay-mode 分支未生效（页面渲染完整 app 盖住视频）② WebView2 透明未与 mpv 的 D3D 兄弟表面合成（透明像素显示父窗口背景/黑色）③ overlay 未创建/错位。

**透明探针**（临时，定位后移除）：`html.overlay-mode.overlay-debug` 半透明红 `rgba(255,0,0,.4)`（styles.css）+ videoOverlayPage.ts 无条件加 `overlay-debug` class + Rust stderr 日志（`[video_overlay] overlay webview created`、`bounds … capture_hwnd -> …`）。判定：视频透红调=合成正常问题在别处；纯红色块=透明合成失效（备选：回退 bar 内弹层，或改第二个顶层透明窗口走 DWM 合成）；无红色=未创建/错位（看 stderr）。

### 探针结果 → 架构转向：子 WebView 透明判定死刑，改独立顶层透明窗口

用户实测「一整块纯红色」→ **WebView2 子窗口的透明像素不与兄弟 HWND（mpv D3D11 表面）做 alpha 合成**，窗口化宿主模式的合成层限制，代码层无解（DefaultBackgroundColor alpha=0 已正确应用，页面样式/分支/z 序均无问题）。

重构 `video_overlay.rs` 为**顶层透明窗口**（DWM 合成顶层 alpha 压过一切下层窗口，含视频）：
- `WebviewWindowBuilder::new(app, "video-overlay", App("index.html"))` + `transparent(true)/decorations(false)/shadow(false)（否则 DWM 阴影会在视频上画出窗口矩形光晕）/skip_taskbar/resizable(false)/visible(false)/focused(false)`。
- **WS_EX_NOACTIVATE** 补丁：`SetWindowLongPtrW(hwnd, GWL_EXSTYLE, ex | WS_EX_NOACTIVATE)`——点弹层不抢主窗口焦点（否则失焦钩子会把自己关掉）。
- **显示用 raw `ShowWindow(SW_SHOWNOACTIVATE)`**，不用 tauri `show()`（SW_SHOW 会激活窗口偷焦点）。
- **z 序**：每次 sync 用 `SetWindowPos(overlay, insertAfter=main_hwnd, NOMOVE|NOSIZE|NOACTIVATE)` 提到主窗口正上方——主窗口激活会埋掉它，激活钩子里同步重提。
- **贴随**：位置取 `GetWindowRect(mpv 宿主)` 屏幕坐标（`native_video::active_video_screen_rect`），免客户区换算；主窗口 Focused(true)/Moved/Resized 钩子触发 sync。**Focused(false) → hide**：不可见窗口不能截胡其他应用的点击。
- native_video.rs：删除 overlay_hwnd 字段/capture_hwnd/apply_bounds 的 z 序舞步；**layout 必须先 drop sessions 锁再调 video_overlay::sync**（std Mutex 不可重入，事件钩子在主线程也会锁它）。
- 前端零改动（除删探针）：顶层窗口矩形==视频矩形，弹层 cmd 的 x/bottom 语义不变，事件协议（cmd/state/volume/hover/wheel/closed + drag-drop 转发）全部沿用。
- 注意：`SetWindowLongPtrW` 在 windows-sys 0.61.2 里是 `windows_link::link!` 宏声明，grep "pub fn" 搜不到；GWL_EXSTYLE=-20。
- 验证：cargo check ✓ / cargo test 28 passed ✓ / tsc ✓。待真机：视频恢复可见、弹层浮在视频上、弹层交互不失焦、失焦自动隐藏。

## 真机反馈：弹层完全不显示 → SetWindowPos 方向 bug（决定性根因）

用户报告音量弹层「还是没显示出来」（不在视频上也不在 bar 里）。诊断链：排除坐标语义（x/bottom 相对视频表面正确）、capabilities（授权完整）、popupMode 切换链路（playerShell 接线正确）→ **`raise_above_main` 写成 `SetWindowPos(overlay, main_hwnd, ...)`——insert-after 语义把 overlay 放到主窗口正下方**，被不透明主窗口完全遮住；视频正常（mpv 在主窗口内部）、事件链路全活、弹层渲染在不可见窗口里，静默失效。

修复 `raise_overlay`：`SetWindowPos(overlay_hwnd, HWND_TOP, 0,0,0,0, SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE)`；另一应用激活时自然越过 overlay，且失焦钩子本来就会隐藏 overlay。sync 内 set_position/set_size 失败改为 eprintln 日志（不 panic）。

### 前端加固包（配套落地）

1. `src/shell/overlayReadiness.ts`（新）：markOverlayReady/isOverlayReady/waitForOverlayReady(timeout)。注意类型坑：waiters 存 `Promise<boolean>` 的 resolve 时数组类型须为 `Array<(wasReady: boolean) => void>`，`() => void` 与 indexOf(resolve) 参数逆变不兼容（tsc 报 TS2345）。
2. `videoOverlayPage.ts`：cmd/state 监听先注册（弹层关键路径，主 webview 切 popupMode 瞬间就可能发 cmd），drag-drop 转发 try/catch 非致命且移到最后；全部注册完 `emit("video-overlay-ready")` 握手。
3. `main.ts`：boot() 注册 `listen("video-overlay-ready", markOverlayReady)`；bootVideoOverlay 加 catch（console.error）。
4. `nativeBackend.ts`：`native_video_overlay` invoke 单独 catch——overlay 失败只 warn 不终止 native 播放（此前失败会连锁触发 videoViewer 整体回退 WebView、销毁正常 mpv 会话）。
5. `videoViewer.ts`：就绪门控 `const ready = isOverlayReady() || await waitForOverlayReady(2000); shell.setPopupMode(ready ? "overlay" : "inline")`——overlay 页没就绪就留在 bar 内兜底（旧行为可见但位置低），不再发进黑洞。
